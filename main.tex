\newcommand{\paperabstract}{%
Assigning source files to reference architecture modules supports conformance checking and system understanding. Identifiers, code content, static dependencies, and directory organization inform this mapping, but their usefulness depends on how they are represented and processed. We investigate the contribution of file representations, folder and member information, and dependency neighbors, defined as files connected by static dependencies. We study nine Java, C, and C++ systems with limited labels, comparing Word2Vec, Node2Vec, and UniXcoder representations with feature-only and graph-based predictors. We vary file, member, and folder graph configurations and conduct controlled dependency comparisons under supervised-only and self-training schedules. Dependency-informed representations provide strong feature-only baselines, while folder nodes yield the largest and most consistent gains among graph configurations. However, these gains largely reflect information available through a directory rule and do not consistently improve predictions for files that depart from it. With file representations held fixed, neighbor access improves a Graph Attention Network (GAT) and a multilayer perceptron (MLP) receiving each file's representation and the mean representation of its neighbors on most systems. In contrast, directed, typed Heterogeneous Graph Transformer (HGT) propagation reduces median macro-F1 on most systems. An undirected graph with a single dependency relation largely removes these losses. Useful dependency information therefore does not necessarily imply beneficial propagation. Evaluations should distinguish information already encoded in file representations from the contribution of neighbor access and assess directory-departing files separately from aggregate performance.
}
