\section{Introduction\label{sec:intro}}

Maintaining a software architecture requires knowing which implementation elements belong to its modules~\cite{parnas1972,clements2003}. This correspondence can become incomplete as a system grows and architectural documentation falls behind the implementation. Code-to-architecture (C2A) mapping addresses this problem by assigning source files to the modules of a reference architecture. When only part of a system has been mapped, automated approaches can use these known assignments together with information from the code and project structure to infer the remaining assignments.

Automated C2A mapping can draw on several sources of evidence. Identifiers express domain concepts and implementation roles, while declarations and operations describe how those responsibilities are implemented. Static dependencies describe interactions between files, and directories record how developers organize a project~\cite{sarif,negar,garcia2013}. These sources need not agree: a utility may interact with several modules, terminology may be shared across responsibilities, and a directory may contain files assigned to different architectural modules. This study examines what dependency-neighbor aggregation and richer graph structures add beyond the information available in file representations and directory organization.

Prior C2A mapping work combines lexical features with static dependencies in graph neural networks~\cite{jabeen2025graph}, with later work also incorporating folder organization~\cite{c2a_mapping}. Related work on architecture recovery, which infers a decomposition without a reference architecture, explores random-walk and graph-autoencoder representations of dependencies~\cite{negar,structsar} and encodings of identifier and folder tokens~\cite{gaer}. When several information sources and predictor mechanisms change together, comparisons of overall performance leave the contribution of additional graph context unclear.

A classifier may already receive dependency information through its input vectors, so the contribution of additional neighbor aggregation needs to be evaluated separately. Similarly, high agreement with a reference architecture may partly reflect agreement between that architecture and the directory structure. A folder-aware model can improve overall accuracy while reducing accuracy on files that a simple directory rule misclassifies. Aggregate scores alone do not distinguish these outcomes. Representing members separately may expose context obscured in a single file-level representation.

We investigate these questions on ten Java, C, and C++ systems, using a bounded labeling budget with at least one labeled file from every module. The setting is transductive: features and graph structure are available for labeled and unlabeled files, while module-label supervision uses only the initially labeled files. We compare lexical Word2Vec, structural Node2Vec, and contextual UniXcoder representations. A multilayer perceptron (MLP) establishes their performance before additional neighbor aggregation. We use a Heterogeneous Graph Transformer (HGT)~\cite{hgt} to compare file, folder, and member configurations, and assess folder-aware predictions against a directory rule using the same labeled files. We also compare performance with neighbors enabled and disabled for HGT, a neighbor MLP, and a Graph Attention Network (GAT)~\cite{gat}, with aggregation in one or both directions.

\noindent The study is guided by three research questions:
\begin{itemize}[leftmargin=1em, itemsep=1pt]
    \item \textbf{RQ1.} How does mapping performance vary across lexical, structural and contextual file representations?
    \item \textbf{RQ2.} How does adding member and folder nodes to file-level HGT change mapping performance, and how do folder-aware predictions compare with a directory rule?
    \item \textbf{RQ3.} How does using dependency neighbors change mapping performance, and how do the predictor and aggregation direction affect this change?
\end{itemize}

The results show that file representations encoding dependency information provide strong starting points, while the benefit of further neighbor aggregation depends on the predictor and aggregation direction. Folder nodes yield the largest gains within the HGT configurations, but the directory rule reaches similar accuracy on most systems, and folder paths supplied directly as file features match or exceed folder nodes on most systems. These overall gains do not consistently extend to files the rule assigns incorrectly. Member nodes provide no consistent improvement with one or two HGT layers.
