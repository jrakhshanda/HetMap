\section{Threats to Validity\label{sec:threats}}

\parg{External validity:} The benchmark contains nine open-source systems in Java, C, and C++, each with one reference decomposition, so the results describe these systems and their reference architectures. All systems had been inspected before the full experiment, and the comparisons were not fixed in advance. The rewiring control, on which the claim that Node2Vec encodes structure beyond node degree rests, covers three systems. Relationships between performance and structural properties are reported as associations, not causal effects, since the benchmark does not allow these properties to be separated from one another or from system size and label availability. Whether the findings extend to other systems, alternative reference decompositions, or the evolution of a mapping over time was not tested.

\parg{Internal validity:} Dependencies are extracted using static analysis, which can miss dependencies that arise only at runtime, for example through reflection, function pointers, conditional compilation, or macro expansion, and can introduce imprecise edges when references cannot be resolved unambiguously. Because the predictors that use neighbors depend on the extracted graph, missing and incorrect edges can affect their predictions. Models with neighbor information on and off are trained separately, so their differences also include differences in learned weights and, under self-training, in pseudo-label histories.

The analyzed source code may not match the version a published mapping describes. Several benchmark mappings were created years before the source versions used here were obtained, and the files included in a system can depend on its build configuration, so the analyzed file set may differ from the one the mapping covers. In older systems, architectural drift may also weaken the correspondence between a file and its assigned module.

Files can plausibly belong to more than one module, and annotators may assign them differently. Because the initial labeled set is sampled from the same mapping used for evaluation, an incorrect assignment can both mislead the model during training and penalize an architecturally plausible prediction.

\parg{Statistical validity:} Repeated splits contain overlapping files, and runs from the same system are not independent system replications, so we report effects per system and do not treat the runs as independent datasets. With 100 runs per configuration, statistical tests may identify small systematic differences that are not practically meaningful, so we report effect sizes alongside significance. These runs capture variation from different initial labeled sets, but not from stochastic model training. The seeds governing model initialization and training were not retained, so an independent rerun would use different training seeds even with the same labeled sets, and the effect of this variation on borderline outcomes was not assessed. The RQ3 experiments record their seeds, but ten splits and three embedding seeds for Node2vec do not cover every source of stochastic variation.

\parg{Construct validity:} Scores measure agreement with a particular reference architecture. Folder layout may reflect the same developer decisions or reconstruction evidence used to define that architecture. Strong directory prediction therefore does not establish independent recovery of architectural intent. Directory purity and neighbor-label conflict use complete reference labels only for retrospective analysis. Training and prediction use the initial labeled set and model-generated pseudo-labels, not true test labels.

Every test file is scored regardless of confidence. In this single-label task, micro-F1 equals accuracy; macro-F1 gives equal weight to modules represented in the test truth. A module whose only file is anchored in training can be absent from that split's macro average. Repair and damage rates have different denominators, and repair is undefined when the directory baseline makes no errors. File/split event counts may include the same file repeatedly. A file spanning several concerns is still forced into a single reference module.

The study is transductive: representation learning and graph processing can use unlabeled test nodes and their edges. It does not establish performance on newly arriving files outside the observed graph. Other information sources, including change history and dynamic dependencies, are outside the evaluated scope.
